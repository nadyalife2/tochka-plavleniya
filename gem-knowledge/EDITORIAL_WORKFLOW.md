# Редакционный конвейер

Содержание и голос: [MASTER_EDITORIAL_BOOK.md](MASTER_EDITORIAL_BOOK.md). Эти два файла — основные редакционные документы. Старые копии голоса и универсальные шаблоны не применяются при противоречии книге. Это приоритет документации, не изменение программных проверок.

## 1. Источники истины
- Формат пакета: schemas/article-contract-v1.1.schema.json; v1.0 — только для совместимости, если её поддерживает delivery_cli.py.
- Программные ID сплавов: theme4/data/materials-registry.php; физические утверждения проверяются первоисточниками.
- Задачи и связи: согласованная активная книга semantic_core, content_plan и interlinking_map.
- Статус публикации: проверенная запись WordPress и URL, не пометка Excel.
Не копировать enum и таблицы температур в каждый промпт. При конфликте книги, схемы, кода и данных остановить соответствующий этап и записать конкретную причину.

## 2. Этапы
1. Планировщик: уникальная тема, интент, границы и приоритет; проверка смысловых дублей.
2. Исследователь: бриф и таблица доказательств, проверенные режимы и риски, явные пробелы.
3. Writer: полный Markdown по типу статьи в голосе главы 2 книги; отдельно служебные блокеры и отложенные связи.
4. Reviewer: независимая проверка и замечания с местом, причиной, действием; вердикт отдельно от ОТК WordPress.
5. Упаковщик: принятый текст → ручная карточка или JSON по действующей схеме.
6. Publisher: подтверждённая доставка только в draft/pending, журнал и read-after-write.
7. Человек: текст, мобильный вид, поля, источники, ссылки; затем ОТК сохранённой редакции и отдельное решение о публикации.
8. Наблюдение: рабочие URL, актуальность и задачи обновления.
Один ассистент может последовательно выполнять роли, но исследование, текст и проверка — отдельные результаты.

## 3. Таблица и статусы
Проверенные листы исходной книги: content_plan, clusters, raw_data, briefs_ТЗ, statiy, interlinking_map, wp_export, image_generation. Не предполагать существование research_report.
Активный файл/Google Sheet и версию уточнить до записи. Строку искать по ID и slug, нормализуя 1/'1'/1.0 для поиска. При дубле ТЗ или конфликте ID не выбирать произвольную строку.
content_plan: article_id, рабочий заголовок, slug, статус, Ответственный_бот, Следующее_действие. briefs_ТЗ — бриф; statiy — текст; wp_export — пакет; interlinking_map — source, target, slug и анкор.
Не менять столбцы и словарь статусов без согласования миграции. При ошибке — причина и одно выполнимое Следующее_действие. «Написано» не равно «проверено» или «опубликовано».

## 4. Ссылки
Сверять ID, slug, анкор, самоссылки, дубли и согласованность двух листов. Обратная ссылка не обязательна: связь направленная и содержательно уместная.
Плановая ссылка не равна рабочему URL. Статус «не начато» не доказывает 404. Проверять фактическую публикацию. Неподтверждённые цели держать в служебной карте, не публиковать кликабельные заглушки.
В исходной книге у №3 пустое поле content_plan, но есть связи в interlinking_map; перед исправлением проверить текущую версию данных.

## 5. WordPress и контракт
Ручной маршрут: заголовок, текст, рубрика, метки, отрывок, применимые поля паспорта, FAQ и источники. Паттерны выбирать по задаче из docs/03-editorial-publishing/GUIDE.md. Не переносить из старых руководств противоречащие книге формулы и нормы.
Автоматический маршрут: JSON → схема → доставка через tools/delivery_cli.py → журнал и перечитывание сохранённой записи → человек. Генератор не присваивает verified.
В проверенной v1.1 обязательны temp_data.kind и temp_data.range даже для не-температурных тем. Не выдумывать градусы и не подставлять «не применимо» ради валидации. Для таких статей — ручной маршрут либо отдельная согласованная правка схемы, генератора, доставки и тестов.
FAQ: 4–6; sources: 2–4 документа, включая даташиты. Сам JSON Schema не сравнивает HTML и массив FAQ: соответствие проверять отдельно.
Markdown front matter не равен JSON: category/alloy не автоматически category_slug/solder_alloy. Упаковщик явно преобразует и валидирует данные.
Не оставлять [web:*], file:///, localhost, фиктивные источники и заглушки в публикации. Проверить, не дублируются ли FAQ и источники между телом и выводом метаполей.
JSON-LD формирует действующий код темы/плагина; не вставлять конкурирующую схему в тело. ОТК подтверждает сохранённую редакцию уполномоченный человек/аккаунт по разрешению владельца. Не вычислять fingerprint по придуманной формуле: использовать реализацию плагина и expected_hash.

## 6. Надёжность и стоимость
Исследовать кластер совместно, применять факты к каждой теме отдельно. Не плодить копии реестра и голоса. Черновики 17 статей из чата требуют повторного технического и безопасностного ревью.
Устойчивый content_id, журнал, защита от перезаписи опубликованных/ручных правок. Конфликт не обходить принудительной повторной записью. Секреты не хранить в инструкциях и журналах.
Проверки: схема, доказательства, ссылки, поля, мобильный вид, отсутствие дублей FAQ, read-after-write. Отчёт называет команду, результат и область; формальное прохождение тестов не доказывает качество статьи.

## 7. Миграция и Git
База: 75e6e62, fix/backup-cron-docs; отдельная docs/editorial-single-source. Голос cd416a5 интегрирован в книгу без переноса непроверенных физических примеров.
CLAUDE.md/AGENTS.md маршрутизируют редакционные задачи на два документа, сохраняя UI/Git. Инструкции Writer/Reviewer и SKILL.md — короткие адаптеры. Остальные старые файлы пока не удалять: при конфликте действует книга, схемы и исполняемый код не переопределяются текстом.
В первом этапе не менять PHP, схемы, архив плагина и delivery_cli.py. Техническое руководство публикации остаётся справкой интерфейса; полный поиск дублей и обновление остальных skills — следующий этап перед объявлением миграции завершённой.
Ссылки из SKILL.md на файлы с пробелами или кириллицей не использовать: tools/check_docs_links.py не декодирует %20. Путь к инструкции роли указывать текстом в обратных кавычках.
До PR выполнить python tests/run-all-tests.py в клоне; проверить ссылки Markdown и согласованность с фактической схемой. Если тесты не запускались, явно сообщить и не объявлять проверку пройденной. Прямой push в main и force-push без разрешения запрещены.
