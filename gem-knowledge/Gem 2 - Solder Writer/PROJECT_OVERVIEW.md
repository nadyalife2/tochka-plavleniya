# PROJECT OVERVIEW — Solder Writer

## Что это за проект

Русскоязычный сайт о пайке с SEO-статьями.
Статьи пишутся не копирайтерами — а системой AI-агентов (Gems в Google Gemini),
настроенных по единым правилам с живым авторским голосом.

Цель: статьи, которые хочется дочитать, сохранить и использовать на практике.
Не SEO-вода. Не учебник. Живой язык практика — как на Хабре или vc.ru.

---

## Зачем это нужно

Обычные SEO-статьи о пайке — это пересказ очевидного, канцелярит и шаблонные списки.
Мы хотим иначе: термин сразу, механизм одной фразой, наблюдение с иронией наблюдателя.
Читатель — новичок по знаниям, коллега по достоинству.

---

## Архитектура системы

### Конвейер Gems (Google Gemini)

Каждый Gem — отдельный AI-агент с системным промптом и набором файлов знаний.

| Gem | Роль |
|---|---|
| Gem 1 — Researcher | Разбирает тему, выделяет риски, структуру, нюансы |
| Gem 2 — SEO Planner | Интент, H2, FAQ, title, meta description |
| Gem 3 — Writer | Пишет статью по шаблону и голосу |
| Gem 4 — Reviewer | Проверяет стиль, факты, SEO, habr-like качество |
| Gem 5 — WordPress Publisher | Готовит title, slug, excerpt, рубрику, теги |

### Google Таблица semantic_core

Листы таблицы:
- `content_plan` — рабочий заголовок и slug (техзадание для Writer)
- `clusters` — обязательные подтемы H2/H3 кластера
- `raw_data` — источник фактов (Writer не выдумывает вне этого листа)
- `research_report` — выход Gem 1, вход для Gem 3

## Голос автора (ключевое)

Определялся через серию выборов. Финальная формула:

```
Термин сразу, без извинений
→ Механизм одной фразой (почему, не только что)
→ Наблюдение или последствие (с лёгкой иронией, если само вышло)
```

Параметры:
- Юмор: только если сам вышел. Натянутый хуже отсутствия.
- Отсылки: любые, если точные и короткие.
- Термины: с первого упоминания, без «так называемого».
- Читатель: не ведём за руку — делимся опытом.
- Канцелярит («является», «осуществляется», «следует») — запрещён.

Эталонные фразы — в `09_voice_and_persona.md`.
