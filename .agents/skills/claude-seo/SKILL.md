# Claude SEO & AEO/GEO Architect Skill

Этот скилл наделяет агента возможностями комплексного аудита и проектирования поисковой оптимизации нового поколения: классический Technical SEO + генеративный поиск (AEO/GEO для Yandex Нейро, Perplexity, ChatGPT Search, Google AI Overviews).

---

## 1. Концепция и зоны ответственности

В эпоху AI-поиска ранжирование строится на двух китах:
1. **Машиночитаемая структура (Machine Extractability):** Нейросети извлекают чистые факты, формулы, диапазоны и первоисточники.
2. **Инженерный E-E-A-T:** Доказательность опыта, ссылки на физические стандарты (ГОСТ, IPC, ISO) и отсутствие AI-галлюцинаций (Anti-Slop).

---

## 2. Ключевые протоколы аудита

### Протокол A: AEO / GEO (Answer Engine Optimization)
- **Принцип Answer First:** Первый абзац статьи (до 40–50 слов) обязан давать прямой, исчерпывающий ответ на поисковый интент (например: точная уставка паяльника для ПОС-61: 260–290 °C).
- **Предикатная плотность:** Наличие структурированных пар «субъект — предикат — объект» (сплав — температура ликвидуса — величина).
- **Спецификация `llms.txt` и `llms-full.txt`:** Наличие корневого манифеста сайта для AI-краулеров со ссылками на документацию и реестры.
- **Таблицы физических величин:** Наличие Markdown-таблиц с единицами измерения (°C, мм, Вт, с), пригодных для прямого парсинга без потерь контекста.

### Протокол B: E-E-A-T & Доказательная база
- **Паспорт верификации:** Хэш статьи (`reviewed_content_hash`), ID проверяющего инженера, дата ревизии.
- **Цитирование стандартов:** Прямые ссылки на ГОСТ (например, ГОСТ 21931-76) и международные регламенты (IPC J-STD-006, IPC-A-610).
- **Авторский голос Practico:** Практический опыт мастера, разбор типичных ошибок новичков, предостережения о перегреве меди и отрыве пятаков.

### Протокол C: Schema.org & Микроразметка
- Валидация JSON-LD графов: `TechArticle`, `HowTo`, `FAQPage`, `WebApplication`.
- Разрешение конфликтов микроразметки (подавление дублей при активных SEO-плагинах, таких как Rank Math).
- Вложенные сущности: автор (`Person`), организация (`Organization`), инструменты (`tool`), материалы (`supply`).

### Протокол D: Core Web Vitals (CWV)
- **LCP (Largest Contentful Paint) < 2.5 с:** Preload критических шрифтов woff2 и LCP-изображений, минимизация блокирующего CSS.
- **INP (Interaction to Next Paint) < 200 мс:** Дебаунс полей ввода (калькуляторы, поиск), исключение синхронного Layout Thrashing в JavaScript.
- **CLS (Cumulative Layout Shift) < 0.1:** Явные атрибуты `width`/`height` для картинок, отсутствие скачков макета при динамической загрузке.

## 3. Матрица приоритизации правок (Action Plan)

Каждый аудит завершается приоритизированной матрицей:
- **P0 (Critical / Blocker):** Грубые ошибки разметки, отсутствие канонических ссылок, дубли H1, блокировка краулеров.
- **P1 (High Impact / AEO):** Внедрение блока прямого ответа, таблицы параметров, микроразметка `FAQPage` и `TechArticle`.
- **P2 (CWV & UX Performance):** Оптимизация шрифтов, сжатие ассетов, дебаунс фильтров, ленивый рендеринг.
- **P3 (Long-term / GEO):** Расширение `llms.txt`, перелинковка кластеров семантического ядра, обогащение датасета.
