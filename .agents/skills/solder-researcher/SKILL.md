# Solder Researcher — Исследователь Тем и Архитектор Статей

Специализированный скилл для глубокого анализа тем, выявления рисков, поиска пробелов у конкурентов и проектирования структуры статьи по пайке для новичков и мастеров.

## When to Use

- При анализе новой темы из семантического ядра (`semantic_core - статьи.csv`).
- При проектировании структуры будущей статьи (заголовки H2/H3, закрывающие реальный пользовательский интент).
- При аудите темы на риски безопасности (ожоги, токсичные флюсы, свинец, ESD, перегрев компонентов).
- При подготовке списка вопросов для блока FAQ.

## Quick Start

**Анализ темы и составление структуры:**
```bash
# Изучите семантическое ядро и определите рабочий slug темы
# Пример: pos61-vs-sn63pb37 или soldering-iron-temperature-guide
```

## 1. Контекст Проекта и Аудитория

- **Аудитория:** Новички, любители, домашние мастера. Объясняем сложное простым и точным языком, без сленга и без заумной терминологии.
- **Главная цель:** Помочь читателю выполнить пайку качественно, правильно и безопасно с первого раза. Никакого текста «ради SEO».
- **Словарь:** Используем строгие термины: *припой*, *флюс*, *жало*, *термопрофиль*, *эвтектика*, *демонтаж*.
- **Безопасность:** Каждая тема проверяется на риски (ожоги, вентиляция паров флюса, свинцовая пыль, заземление, антистатика). Если риск существует — он обязательно выносится в специальный блок статьи.

---

## 2. Работа с Семантическим Ядром (`semantic_core`)

1. **Лист `content_plan`:** Рабочий заголовок и slug текущей темы — первичное техзадание.
2. **Лист `clusters`:** Колонка «ключевые темы» и «пробел у конкурентов». Структура должна закрывать то, чего не хватает в существующих материалах интернета.
3. **Лист `raw_data`:** Исходные технические данные и авторитетные источники. Факты берутся строго из проверенных источников, домыслы запрещены.
4. **Лист `competitors`:** Изучение недостатков конкурентов (поверхностная подача, вода, устаревшие советы) для формирования практического превосходства.

---

## 3. Формат Выходного Отчёта

Каждое исследование темы возвращает структурированный бриф:

1. **Интент читателя:** Что именно хочет узнать и сделать пользователь (проблема, боль, задача).
2. **Обязательные технические тезисы:** Какие ключевые параметры (температура, сплав, флюс, инструмент) должны быть раскрыты.
3. **Ошибки и риски:** Где новичок гарантированно ошибётся или испортит плату/инструмент.
4. **Проект структуры статьи (Outline):**
   - H1: Ёмкий, понятный заголовок с сутью и slug.
   - Введение: Сразу к сути, без прелюдий.
   - H2/H3: Вопросы в формулировках пользователя («Как выбрать температуру», «Чем опасен перегрев дорожек»).
   - Интерактивный блок / калькулятор: Рекомендация к использованию.
5. **Список вопросов для FAQ:** 3–5 практических вопросов с краткими тезисами ответов.

---

## 4. Требования к Стилю (Habr-Like)

- Начинать сразу с сути и пользы.
- Делиться реальными нюансами монтажа, а не пересказывать очевидное.
- Писать спокойно, аргументированно, как опытный инженер-наставник.
- Никакого фальшивого личного опыта («я вчера взял паяльник и проверил»).
