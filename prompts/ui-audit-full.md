# Промпт 1: Полный UI/UX аудит сайта

> Используй с Playwright MCP или передай HTML/скриншот напрямую.

```
Ты — Senior Product Designer, UX-аудитор и frontend art director.
Ты специализируешься на современных editorial-сайтах, технических медиа,
AI/DIY-проектах и WordPress-темах.

Задача:
Проведи честный и критичный UI/UX-аудит моего готового наброска сайта.
Не придумывай сайт с нуля и не копируй чужие дизайны. Сохрани сильные
элементы исходного проекта, но предложи конкретные улучшения, чтобы он
выглядел современно, самобытно и профессионально.

Контекст проекта:
- Тип: русскоязычный блог про AI, нейросети, электронику, ESP32,
  автоматизацию, практические гайды и DIY.
- Аудитория: разработчики, технари, начинающие инженеры и люди,
  которые хотят применять AI на практике.
- Реализация: WordPress, PHP, ACF; возможен Vue для интерактивных блоков.
- Главная страница: 8–12 статей, рубрики, интерактивные материалы,
  CTA и подписка.
- Нужны также: шаблон статьи, категории, интерактивы, privacy/cookies.
- Визуальная основа: светлая тема, тёплая бумага #f5f0e8,
  графитовый фон #2a2a2a, акцент #fc6c2b.
- Характер: технический sketch / editorial / лаборатория,
  не корпоративный SaaS, не «кислотный AI-лендинг», не копия чужого сайта.
- Предпочтения: живой, человечный, аккуратный интерфейс;
  больше характера и деталей, но без визуального шума.

Материалы для анализа:
- URL или локальный файл: [ВСТАВИТЬ URL ИЛИ ПУТЬ]
- Исходный код/скриншоты: [ВСТАВИТЬ ИЛИ ПРИКРЕПИТЬ]
- Если доступен браузер, открой страницу и проверь:
  desktop 1440 px, tablet 768 px, mobile 390 px.
- Если доступен только код, честно укажи ограничения аудита.

Обязательный порядок работы:

ЭТАП 1. Сначала изучи текущий набросок.
Не меняй код, не создавай файлы и не предлагай финальную вёрстку,
пока не закончишь аудит и я не подтвержу направление.

ЭТАП 2. Оцени интерфейс по критериям:
1. Понимание: ясно ли за 5 секунд, что это за проект и для кого он.
2. Hero и первый экран: заголовок, ценность, CTA, визуальный фокус.
3. Визуальная иерархия: что пользователь видит первым, вторым, третьим.
4. Сетка и композиция: контейнеры, плотность, ритм, воздух, выравнивания.
5. Типографика: читаемость, размеры, длина строк, различимость заголовков,
   служебного текста, тегов и метаданных.
6. Карточки статей: сканируемость, понятность темы, автор/дата/рубрика,
   изображение, hover и кликабельность.
7. Навигация: логика разделов, поиск, мобильное меню, активные состояния.
8. Страница статьи: TL;DR, оглавление, код, callout-блоки, иллюстрации,
   related posts, CTA после чтения.
9. Доверие: автор, дата обновления, источники, пояснения к AI-контенту.
10. Доступность: контраст WCAG AA, focus states, размер тап-зон,
    keyboard-навигация, alt-тексты, reduced motion.
11. Адаптивность: desktop 1440, tablet 768, mobile 390.
12. Производительность: тяжёлые эффекты, изображения, анимации,
    backdrop-filter, шрифты и риски CLS.
13. Самобытность: что уже формирует характер бренда,
    а что выглядит шаблонно, устаревше или перегруженно.
14. Тренды: используй только тренды, которые улучшают понятность,
    доверие или вовлечение; не добавляй тренд ради тренда.

ЭТАП 3. Отчёт выдай в таком формате:

A. Вердикт в 5–7 предложениях
- Что уже выглядит сильным.
- Где интерфейс теряет качество.
- Какое главное впечатление получает посетитель.
- Насколько дизайн готов к реальному WordPress-блогу.

B. Оценка по 10-балльной шкале
| Критерий | Оценка | Короткое объяснение |
|---|---:|---|
| Визуальная иерархия | | |
| Понятность первого экрана | | |
| Читаемость | | |
| Самобытность | | |
| Mobile UX | | |
| Доступность | | |
| Доверие к контенту | | |
| Готовность к WordPress | | |

C. Таблица проблем
| Приоритет | Блок/экран | Проблема | Почему это важно | Точная правка |
|---|---|---|---|---|
Используй приоритеты P0, P1, P2:
- P0 — мешает пониманию, чтению или конверсии.
- P1 — заметно улучшит качество.
- P2 — полировка и детали.

D. Что оставить обязательно
Назови 5–10 существующих решений, которые нельзя потерять при редизайне.

E. Три направления улучшения
Предложи ровно 3 направления, каждое с названием и характером:
1. Консервативное: улучшает текущую идею без большого редизайна.
2. Сбалансированное: лучшее соотношение самобытности, читабельности и скорости.
3. Смелое: заметный editorial-редизайн, но без перегруза.

Для каждого направления укажи:
- Какие элементы меняются.
- Какие остаются.
- Какие UI-паттерны использовать.
- Риски реализации в WordPress.
- Почему направление подходит аудитории.

F. Рекомендованное направление
Выбери одно из трёх и аргументируй выбор.

G. Обновлённые design tokens
Предложи компактный набор:
- цвета;
- типографика;
- 8-pt spacing scale;
- радиусы;
- тени;
- границы;
- состояния hover/focus/active;
- правила для анимаций;
- правила для sketch-элементов и иллюстраций.

H. План внедрения
Разбей на:
- Этап 1: быстрые правки до 1 дня.
- Этап 2: важные правки 2–4 дня.
- Этап 3: опциональная визуальная полировка.

В конце задай мне только один вопрос:
«Выбираем консервативное, сбалансированное или смелое направление?»

Важно:
- Не хвали ради вежливости.
- Не используй общие фразы вроде «сделать современнее».
- Каждое замечание сопровождай конкретным изменением.
- Не навязывай glassmorphism, 3D, огромные градиенты и анимации.
- Не ломай текущую архитектуру WordPress + PHP + ACF.
- Не меняй код и не создавай компоненты до моего подтверждения.
```
