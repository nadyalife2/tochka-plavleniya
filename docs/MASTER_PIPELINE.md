# Генеральный сквозной конвейер «Точка Плавления»

Документ описывает целевую цепочку: от темы до черновика WordPress, редакционной проверки и последующей публикации. Автоматическая публикация запрещена.

## Статус реализации

| Блок | Статус |
|---|---|
| JSON-контракт статьи | Реализован в `schemas/article-contract-v1.schema.json` |
| Валидация REST-метаполей | Реализована в `tchp-content` |
| Отпечаток статьи и `expected_hash` | Реализованы в `tchp-content` |
| Генерация статьи через Gemini | Реализована, но требует проверки на реальном WordPress |
| Адаптер «контракт статьи → WordPress payload» | Добавлен в `tools/ai_article_generator.py` |
| Запуск пяти отдельных AI-скиллов из CLI | Не подключён |
| Интеграционный тест на настоящем WordPress | Не выполнен |
| Автоматическое самообучение Build Partner | Инструкция есть; фоновая автоматизация не настроена |

## Целевая цепочка

```text
Тема и SEO/GEO-ТЗ
→ исследование и проверка фактов
→ статья в голосе Practico
→ редакторская и техническая проверка
→ нормализация и валидация JSON
→ создание черновика WordPress
→ ручная редакторская проверка
→ подтверждение expected_hash
→ отдельное решение о публикации
```

## Контракт статьи

Источник истины — `schemas/article-contract-v1.schema.json`.

Обязательные поля:

- `content_id`
- `schema_version`
- `title`
- `slug`
- `excerpt`
- `category_slug`
- `tags`
- `reading_time`
- `difficulty`
- `solder_alloy`
- `temp_data`
- `tools`
- `content_html`

Дополнительные поля:

- `content_hash`
- `faq`
- `sources`
- `standard_data`

Разрешённые идентификаторы сплавов:

```text
pos61, sn63pb37, pos40, sac305, sac405,
sn42bi58, snbiago, roze, vuda, universal
```

Алиасы нормализуются до валидации:

```text
wood -> vuda
rose -> roze
```

## Голос автора

Статьи пишутся в голосе Practico:

- термин;
- механизм одной фразой;
- наблюдение или последствие.

Наблюдаемые признаки процесса обязательны там, где они уместны: цвет, блеск, текучесть, дым, звук, время.

Запрещено:

- выдумывать личный опыт;
- имитировать измерения или фотографии;
- использовать кулинарные метафоры;
- давать обещания без механизма;
- подменять факт стилем.

При конфликте стиля и факта факт имеет приоритет.

## Генерация и доставка

`tools/generate_article_cli.py`:

1. Получает тему.
2. Запрашивает структурированный ответ модели.
3. Нормализует ответ к контракту TCHP.
4. Проверяет обязательные поля и допустимые значения.
5. Сохраняет локальный JSON и HTML-предпросмотр.
6. В режиме доставки создаёт только `draft` или `pending`.

Автоматический статус `publish` запрещён:

- в CLI;
- в `WordPressPublisher`;
- в целевой конфигурации учётной записи автоматизации.

## WordPress и верификация

Плагин `tchp-content` отвечает за:

- регистрацию метаполей;
- REST-валидацию;
- защиту от затирания существующих полей;
- расчёт SHA-256 отпечатка;
- подтверждение редакции через `expected_hash`;
- сброс статуса после изменения проверенного содержимого.

Отпечаток рассчитывает `tchp_calculate_article_hash()`.

Он включает:

- заголовок;
- содержимое;
- excerpt;
- инструменты;
- FAQ;
- источники;
- сплав;
- тип, диапазон и пик температуры;
- стандарт, класс и описание стандарта.

Отпечаток подтверждает соответствие проверенной редакции, но не заменяет техническую экспертизу.

## GEO и разметка

GEO основан на понятной странице:

- прямой ответ в начале;
- самостоятельные разделы;
- проверяемые факты;
- источники;
- корректные даты;
- FAQ только при реальной потребности.

`llms.txt` не является гарантией индексации или цитирования в AI-поиске. Google указывает, что для появления в Search, включая AI-функции, не требуется специальный `llms.txt`, отдельный AI-файл или специальная Schema.org-разметка.

JSON-LD должен соответствовать видимому содержимому страницы. Наличие JSON-контракта статьи не доказывает корректность JSON-LD.

## Тестирование

`tests/run-all-tests.py` проверяет:

- JSON Schema и пример;
- синтаксис отдельных PHP-файлов;
- mock-тесты REST-логики;
- нормализацию сплавов;
- отпечаток;
- уникальность якорей в изолированном сценарии;
- сборку ZIP-архивов.

Это не интеграционный тест настоящего WordPress.

Перед подключением рабочего сайта требуется сквозной тест:

```text
валидный контракт
→ настоящий Publisher
→ создание черновика
→ чтение созданной записи
→ сравнение метаполей
→ подтверждение expected_hash
→ изменение FAQ
→ проверка сброса верификации
→ авторизованный предпросмотр
→ проверка DOM и JSON-LD
```

## CI

GitHub Actions запускает тесты и собирает ZIP-артефакты. Он не разворачивает WordPress, не создаёт базу данных и не выполняет браузерную проверку страницы.

Поэтому CI подтверждает качество кода и артефактов, но не доказывает работоспособность опубликованной статьи.

## Самообучение

Build Partner анализирует подтверждённые замечания и предлагает изменения правил или скиллов.

Правило становится постоянным только после:

- указания источника;
- проверки актуальности;
- проверки конфликтов;
- вашего одобрения;
- внесения изменения.

Предложение ассистента или старый отменённый совет не становится правилом автоматически.
