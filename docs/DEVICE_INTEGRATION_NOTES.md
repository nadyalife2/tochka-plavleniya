# Заметки по интеграции аппаратных узлов: Xiaomi Redmi Note 4 (Node-3)

## 📌 Проблема: Ручной запуск и отвал приложения Triad Omni

### Симптомы:
1. При запуске мобильного приложения **Triad Omni** на Redmi Note 4 узел не стартовал, потому что приложение ожидает уже работающий веб-сокет на `http://127.0.0.1:8000`.
2. Если роутер в Termux не запущен вручную, приложение вылетает либо зависает на белом экране.
3. В скрипте `START_REDMI_DECK.bat` стояла старая ссылка на несуществующий файл `~/start_deck.sh`, тогда как физический рабочий скрипт в Termux называется `~/start_router.sh` (и исполняемый модуль `omni_fast_router_v4_9.py`).

---

## 🛠️ План доработки мобильного приложения Triad Omni (APK / Kiosk):

1. **Автозапуск сервиса роутера при старте приложения:**
   - Добавить в приложение вызов Termux Intent (`com.termux.RUN_COMMAND` / Termux:Tasker) для старта скрипта:
     `sh /data/data/com.termux/files/home/start_router.sh`
   - Альтернатива: сделать автозапуск через `~/.termux/boot/start_gateway.sh` с `termux-wake-lock`, чтобы роутер поднимался сразу при включении телефона без участия пользователя.

2. **Экран ожидания готовности сокета (Splash Loader):**
   - Вместо падения по таймауту сделать экран с пульсирующим логотипом:  
     *«Инициализация Triad-Omni Router на порту :8000...»*
   - Проверять опрос эндпоинта `GET http://127.0.0.1:8000/health` с интервалом 500 мс.
   - Как только получен 200 OK — моментально открывать основной пульт.

3. **Синхронизация имён файлов:**
   - Создать в Termux симлинк: `ln -s ~/start_router.sh ~/start_deck.sh`, чтобы все внешние скрипты с ПК гарантированно находили нужный файл вне зависимости от названия.
