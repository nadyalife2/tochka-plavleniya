# Раздел 2: Установка и настройка WordPress

Пошаговое руководство по развёртыванию, конфигурированию и проверке рабочего или тестового стенда WordPress для проекта «Точка Плавления».

> [!IMPORTANT]
> **Принцип фиксации состояний:**  
> Инструкции в Git описывают целевую конфигурацию. Реальные настройки WordPress хранятся в базе данных MySQL хостинга.  
> Для каждого шага фиксируйте реальный статус:
> * `[РЕКОМЕНДОВАНО]` — параметр утверждён архитектурой, но требует ручной настройки на сервере.
> * `[НАСТРОЕНО]` — конфигурация внесена администратором в панели управления WP.
> * `[ПРОВЕРЕНО]` — работоспособность подтверждена автоматическим или ручным тестом.

---

## 1. Системные требования к хостингу

* **PHP:** Версия 8.1 или 8.2 (с расширениями `curl`, `json`, `mbstring`, `zip`, `openssl`).
* **СУБД:** MySQL 8.0+ или MariaDB 10.5+ с поддержкой `utf8mb4`.
* **Веб-сервер:** Nginx с FastCGI или Apache 2.4 с `mod_rewrite`.
* **Безопасность:** Активный SSL-сертификат (HTTPS обязателен для работы Application Passwords).

## 2. Пошаговый регламент развёртывания

### Шаг 1: Подготовка и резервная копия
1. Если настраивается существующий сайт — создайте полный снимок базы данных через хостинг или `mysqldump`:
   ```bash
   wp db export backup-before-setup.sql
   ```
2. Сделайте резервную копию каталогов `wp-content/themes` и `wp-content/plugins`.

### Шаг 2: Установка контентного ядра `tchp-content` (архив `tchp-content.zip`)
1. В панели управления WordPress перейдите: **Плагины → Добавить новый → Загрузить плагин**.
2. Выберите архив текущей сборки — `tchp-content.zip` (v1.1.1; каноническая папка внутри — `tchp-content`) — и нажмите **Установить → Активировать**.
3. **Проверка:**
   * В меню администратора не должно появиться фатальных ошибок.
   * При открытии любой записи в метабоксе «Паспорт статьи» должны быть: опция припоя **«— не применимо —»**, чекбокс **«Температурный режим применим к этой статье»**, подсказки стандартов и таблицы оснастки/FAQ/источников.
   * В списке **Записи** появилась колонка **GEO** с показателем `N/6`.

### Шаг 3: Установка темы `theme4` (архив `theme4.zip`)
1. Перейдите: **Внешний вид → Темы → Добавить новую → Загрузить тему**.
2. Выберите `theme4.zip` (v4.0.0; каноническая папка внутри — `theme4`), нажмите **Установить → Активировать**.
3. **Проверка визуального отображения (согласно tokens.css):**
   * Перейдите на главную страницу сайта: должен отображаться макет Bento-Sketch Hybrid на светло-сером фоне (`--color-bg: #f6f6f6`), с четкими контурами карточек (`#111111`) и янтарно-жёлтым акцентом канифоли (`--color-accent: #FFC700`). В тёмной теме фон переключается на `#121212`.

### Шаг 4: Настройка постоянных ссылок (Permalinks) и веб-сервера
1. В панели перейдите: **Настройки → Постоянные ссылки**.
2. Выберите структуру: **Название записи** (`/%postname%/`).
3. Нажмите **Сохранить изменения**.
4. **Важное замечание по веб-серверу:**
   * На Apache сохранение постоянных ссылок автоматически обновляет файл `.htaccess`.
   * На Nginx WordPress **не изменяет** конфигурацию сервера автоматически.
   * **На управляемом хостинге:** проверьте работу постоянных ссылок и REST API; при возникновении 404 обратитесь к настройкам панели управления или в техподдержку хостинга.
   * **На собственном VPS/VDS сервере:** убедитесь, что в соответствующем блоке `server` / `location` виртуального хоста Nginx настроена обработка ссылок WordPress (типовой фрагмент: `try_files $uri $uri/ /index.php?$args;`). Не редактируйте общий `/etc/nginx/nginx.conf` вслепую.

### Шаг 5: Настройка базовых рубрик (Таксономии)
1. Перейдите: **Записи → Рубрики**.
2. Создайте 4 канонические рубрики:
   * **Старт в пайке** (ярлык: `start`)
   * **Материалы и флюсы** (ярлык: `materialy`)
   * **Практика пайки** (ярлык: `praktika`)
   * **Ошибки и диагностика** (ярлык: `oshibki`)
3. *Важно:* Ярлыки (slugs) должны точно совпадать со схемой контракта статьи.
4. **Фактический ярлык рубрики «Старт и база»** в рабочей базе — `старт-и-база`
   (в URL выглядит percent-encoded). Тема и импорт понимают также `start` и
   `start-i-baza`. Не переименовывайте ярлык после публикации без 301-редиректа.

### Шаг 6: Настройка пользователя автоматизации и сервисной роли
Для безопасной работы скриптов доставки (`delivery_cli.py`, `ai_article_generator.py`) создаётся выделенный сервисный пользователь с минимально необходимыми правами.

> [!CAUTION]
> **Стандартная роль «Автор» (Author) запрещена для автоматизации:**  
> В ядре WordPress пользователь с ролью Author имеет неотъемлемое право `publish_posts` (публикация собственных записей). Назначение роли Author создаёт прямой риск несанкционированной публикации в обход ОТК и редактора.

**Допустимые варианты роли:**
1. **Встроенная роль «Участник» (Contributor):**
   * Обладает правами создания и редактирования своих записей только в статусе `draft` или `pending`.
   * Не может публиковать статьи (`publish_posts` отсутствует).
   * Ограничение: не может загружать медиафайлы (`upload_files` отсутствует).
2. **Специальная сервисная роль `tchp_automation`:**
   * Если автоматизации требуется загружать иллюстрации к черновикам, создаётся выделенная роль с явным списком возможностей:
     * **Разрешено:** `read`, `edit_posts`, `delete_posts`, `upload_files`.
     * **Строго запрещено:** `publish_posts`, `edit_published_posts`, `delete_published_posts`, `edit_others_posts`, а также кастомное capability верификации `tchp_review_content`.
   * *Примечание:* Простое переименование роли не задаёт ограничений — список capabilities должен быть явно сконфигурирован в коде плагина или через WP-CLI (`wp role create ...`).

**Генерация пароля приложения (Application Password):**
1. Откройте профиль пользователя автоматизации в WP-admin.
2. Прокрутите до раздела **Пароли приложений** (Application Passwords).
3. Введите название: `TCHP Delivery Engine CLI`.
4. Нажмите **Добавить новый пароль приложения**.
5. Скопируйте сгенерированный 24-значный пароль (например, `xxxx xxxx xxxx xxxx`).
6. Сохраните его в переменные окружения вашей машины:
   ```bash
   set WP_URL=https://tochka-plavleniya.ru
   set WP_USER=automation_bot
   set WP_PASS=xxxx xxxx xxxx xxxx
   ```

### Шаг 7: Проверка доступности REST API
Выполните контрольный запрос в консоли:
```bash
curl -i -u "automation_bot:xxxx xxxx xxxx xxxx" "https://tochka-plavleniya.ru/wp-json/wp/v2/users/me"
```
**Критерий успеха:** Ответ `HTTP 200 OK` с JSON-профилем пользователя `automation_bot`.

## 4. Проверка готовности развёртывания (Checklist)

Перед запуском доставки статей проверьте сайт по контрольным точкам:
- [ ] Сайт открывается по HTTPS без предупреждений браузера.
- [ ] Постоянные ссылки работают без `index.php` в URL.
- [ ] Рубрики `start`, `materialy`, `praktika`, `oshibki` созданы с точными слагами.
- [ ] Сервисный пользователь создан с правами `Contributor` или выделенной ролью `tchp_automation` (без права `publish_posts`).
- [ ] Запрос к `/wp-json/wp/v2/users/me` возвращает `200 OK`.
- [ ] Файл `/robots.txt` разрешает индексацию и содержит директиву `Sitemap: ...`.
- [ ] Файл `/sitemap_index.xml` доступен и генерируется Rank Math.
- [ ] Файл `/llms.txt` размещён в корне (не является обязательным для AI-функций Google и не гарантирует попадание в AI Overviews, но служит структурированным индексом для LLM-ассистентов).
- [ ] Локальный тест доставки `tools/delivery_cli.py send-draft` успешно создает черновик.
- [ ] Интеграционный тест `tools/test_live_wp_integration.py` выполнен без ошибок на тестовом инстансе.
