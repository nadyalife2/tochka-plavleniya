# Модуль 20. On-page SEO и GEO

**Когда читать.** Когда бриф готов и Вы собираете страницу: заголовки, первый абзац, мета-поля, FAQ, паспорт статьи. Модуль отвечает на вопрос, как текст выглядит для Яндекса и для ИИ-поиска, и что заполнить до SEO-ревью.

## Вход

| Что нужно | Где взять | Зачем |
|---|---|---|
| Бриф по 13 пунктам | лист `briefs_ТЗ` | интент, тип, план H2, факты |
| Черновик текста | Ваш файл статьи | предмет проверки |
| Кластер и ключевые темы | лист `clusters` | LSI и метки |
| Канонический сплав | `../../theme4/data/materials-registry.php` | поле `tchp_solder_alloy` |
| Правила разметки | §6 `../../docs/03-editorial-publishing/GUIDE.md` | поля паспорта и JSON-LD |
| Модель оценки | `../_SPEC.md` §3 | порог блока `seo` |

## Выход

- готовый каркас H1 + 4–6 H2 + Answer First;
- `<title>` ≤ 60 знаков и `description` ≤ 160 знаков;
- 4–6 пар FAQ;
- заполненный паспорт статьи (`tchp_*`);
- LSI-термины в естественных местах;
- статья, проходящая блок `seo` оценки без ручных правок разметки.

## Статус после шага

| Было | Стало | Что должно существовать |
|---|---|---|
| `writing` | `written` | каркас, мета-поля, FAQ, паспорт, LSI |
| `written` | `review` | on-page проверен по чек-листу ниже |
| любой | `blocked` | невозможно выполнить on-page требование, причина записана |

## Шаг 1. Определите каркас по типу статьи

Тип пришёл из брифа. Каркас не выдумывается заново: он следует типу.

| Тип | H1 | Скелет H2 |
|---|---|---|
| 1. Инструкция | действие + объект + ключевое условие | подготовка, шаги, контроль результата, если не получилось |
| 2. Выбор | «что выбрать», «чем отличается», «что лучше» | вердикт, сценарии, критерии, таблица, ограничения |
| 3. Диагностика | симптом + «как исправить» | симптом, причины, проверка, исправление, точка невозврата |
| 4. Справочник | «виды», «маркировка», «состав» | область применения, сводная таблица, расшифровка, особенности |
| 5. Безопасность | «чем опасен», «как защититься» | опасности, СИЗ, вентиляция, действия при ЧП |

**Критерий готовности:** H1 называет интент без кликбейта, под ним 4–6 H2, порядок H2 совпадает с типом.

## Шаг 2. Проверьте H1

1. H1 отвечает на главный вопрос брифа, а не описывает рубрику.
2. В H1 нет «всё о», «секреты», «шок», обещаний результата без опыта.
3. H1 не дублирует `<title>` слово в слово, если они разведены в шаблоне.
4. В ручном маршруте заголовок записи уходит и в `<title>`, и в `<h1>`: тогда он обязан уложиться в 60 знаков. Если `<title>` переопределяется полем SEO Title, заполняйте оба поля в `wp_export`.

**Критерий готовности:** H1 = интент брифа, длина в лимите `<title>`, запрещённых обещаний нет.

## Шаг 3. Напишите Answer First

Первый абзац даёт прямой ответ. Норма — до 40 слов, обычно 1–3 предложения.

| Признак | Плохо | Хорошо |
|---|---|---|
| Зачин | «В современном мире электроника окружает нас повсюду» | «Холодная пайка — шов, который застыл при подвижке детали» |
| Определение из учебника | «Пайка — это технологический процесс соединения металлов» | «Жало греет детали, а не припой: припой плавится от них» |
| Ответ отложен | «Сначала разберёмся с теорией» | ответ в первом предложении, теория ниже |
| Вопрос к читателю | «Знакомо? Тогда читайте дальше» | утверждение и механизм |

Проверка: прочитайте только первый абзац. Если ответ на запрос не ясен — переписывайте, не добавляйте абзацы.

**Критерий готовности:** в первом абзаце есть прямой ответ, он укладывается в 40 слов, зачина-разгона нет.

## Шаг 4. Соберите title и description

| Поле | Лимит | Куда идёт | Что проверяет оценка |
|---|---|---|---|
| Title | ≤ 60 знаков | `<title>`, сниппет | длина, наличие интента, без кликбейта |
| Description | ≤ 160 знаков | мета-описание, сниппет | длина, прямой ответ, без «в этой статье» |
| Slug | латиница, дефисы | URL | совпадает с мастером, не меняется без владельца |
| H1 | по шагу 2 | страница | совпадает с интентом |

Description — не анонс, а ответ: что читатель узнает и при каких условиях. Формулировки «В этой статье мы расскажем» съедают лимит и ничего не обещают.

**Критерий готовности:** title ≤ 60, description ≤ 160, оба содержат предмет статьи, slug из мастера не изменён.

## Шаг 5. Держите объём и блоки расширения

Целевой объём — 5 500–7 000 знаков с пробелами, включая таблицы и FAQ. Объём растёт смысловыми блоками.

| Блок | Прирост | Что внутри |
|---|---:|---|
| Где ошибаются | 500–700 | типичное заблуждение и цена ошибки |
| Признаки результата | 400–600 | что видно и измеримо после шага |
| Нюансы | 500–800 | 2–4 неожиданные ситуации |
| Диагностика | 400–700 | таблица «симптом → причина → решение» |
| Сравнение | 300–500 | варианты по одинаковым параметрам |
| FAQ | 400–600 | 5–6 реальных вопросов |
| Если не получилось | 300–500 | откат и повтор |

Берите 3–4 блока и останавливайтесь, когда объём достигнут. Вода, повтор Answer First и вывод-пересказ объёмом не считаются.

**Критерий готовности:** объём в диапазоне, 3–4 блока расширения присутствуют, повторов нет.

## Шаг 6. Используйте паттерны осознанно

| Паттерн | Когда нужен | Как выглядит в проекте |
|---|---|---|
| TL;DR | первый абзац с ответом | `tochka-plavleniya/tldr-center`, лид-абзац |
| Warning | риск термоудара, отрыва дорожки, вреда здоровью | `tochka-plavleniya/safety-warning`, блок «Внимание» с условиями |
| Steps | технологическая операция | `steps-list`, нумерованные шаги с контрольной точкой |
| Symptom → Cause → Action | разбор брака | «Симптом: матовый шов. Причина: подвижка при кристаллизации. Решение: фиксация до застывания» |
| Сравнительная таблица | выбор из 2–5 вариантов | одинаковые параметры в колонках |
| FAQ | реальные вопросы читателя | `tchp_faq_items`, массив `q`/`a` |
| Источники | доказательная база | `tchp_sources`, 2–4 документа |

Правило простое: паттерн остаётся, если без него читатель теряет действие, признак или ограничение. Все паттерны в одну статью не вставляются.

**Критерий готовности:** каждый использованный паттерн оправдан, Warning стоит там, где есть риск, Steps не заменяет объяснение механизма.

## Шаг 7. Соберите FAQ

| Требование | Как проверить |
|---|---|
| 4–6 вопросов | посчитайте пары `q`/`a` |
| Вопрос из практики | он звучит как вопрос новичка, а не как заголовок H2 |
| Ответ 1–3 предложения | ответ не пересказывает раздел целиком |
| Нет дубля с телом | вопрос не повторяет H2 дословно |
| Нет дубля в предпросмотре | блок выводится один раз, а не дважды |
| Есть действие или число | ответ ведёт к решению |

FAQ заполняется в `tchp_faq_items`. Если FAQ есть и в тексте, и в метаполе, они совпадают по смыслу.

**Критерий готовности:** 4–6 пар, ответы короткие, двойного вывода блока нет.

## Шаг 8. Заполните паспорт статьи

| Поле | Что содержит | Когда заполняется |
|---|---|---|
| `tchp_solder_alloy` | канонический ID сплава | темы о пайке, сплавах, монтаже |
| `tchp_temp_kind` | тип температуры | если режим применим |
| `tchp_temp_range`, `tchp_temp_peak` | диапазон и пик | вместе с типом, только проверенные числа |
| `tchp_standard`, `tchp_standard_class` | стандарт и класс | IPC-A-610, ГОСТ, J-STD |
| `tchp_standard_description` | пояснение класса | для читателя и для `additionalProperty` |
| `tchp_tools` | инструменты: название, модель, назначение | всегда для практических тем |
| `tchp_faq_items` | 4–6 пар `q`/`a` | всегда |
| `tchp_sources` | 2–4 источника | всегда |
| `tchp_review_status`, `tchp_reviewer_id`, `tchp_reviewed_at` | ОТК | на этапе приёмки |
| Сложность, время чтения | `difficulty`, `reading_time` | при упаковке |

| Тип темы | Сплав | Температуры | Стандарт |
|---|---|---|---|
| Пайка, сплавы, BGA/SMD | конкретный из реестра | да, чекбокс включён | IPC-A-610G, ГОСТ |
| Дефекты и брак | конкретный или «не применимо» | если разбирается режим | IPC-A-610G |
| Оборудование, жала, фены | «— не применимо —» | как правило нет | пусто или профильный |
| Химия: флюсы, пасты, отмывка | «— не применимо —» | если про режимы | J-STD-004 |
| Организация места, ESD | «— не применимо —» | нет | ANSI/ESD S20.20 |

«Не применимо» — рабочее значение, а не заглушка. Подставлять градусы ради заполненности запрещено: пустые и неприменимые поля в разметку не попадают.

**Критерий готовности:** обязательные поля заполнены, температуры подтверждены паспортом факта, «не применимо» выставлено осознанно.

## Шаг 9. Проверьте JSON-LD и не трогайте его руками

Разметку собирает тема и плагин из паспорта. Вручную в HTML-тело JSON-LD не вставляется и не дублируется во вкладке Schema.

| Узел | Источник | Что проверить после публикации |
|---|---|---|
| `TechArticle` или `Article` | тема либо Rank Math | один узел, есть `headline`, `inLanguage`, `keywords` |
| `additionalProperty` | `tchp_solder_alloy`, `tchp_temp_*`, `tchp_standard*` | значения совпадают с текстом |
| `FAQPage` | `tchp_faq_items` | вопросы те же, что на странице |
| `BreadcrumbList` | рубрика и вложенность | крошки ведут на живые URL |
| `citation` | `tchp_sources` | 2–4 источника, реальные документы |
| `reviewedBy` | `tchp_review_*` | дата и проверяющий заполнены после ОТК |

Два режима: с модулем rich-snippet Rank Math печатает `Article`, а факты из паспорта подмешиваются фильтром; без модуля полную схему печатает тема. Дублировать припой и температуры в Schema вручную не нужно.

**Критерий готовности:** в исходном коде один блок JSON-LD, `additionalProperty` заполнен из паспорта, ручных копий нет.

## Шаг 10. Введите LSI без переспама

1. Возьмите ключевые темы кластера и `LSI_и_Сущности` из брифа.
2. Отберите 8–12 терминов: названия сплавов, стандарты, инструменты, дефекты.
3. Введите каждый термин туда, где он уместен: таблица, шаг, FAQ. Не в заголовок ради заголовка.
4. Следите, чтобы синонимы не подменяли сущности: припой и флюс, паста и флюс-гель, мощность и температура — разные вещи.
5. Не вставляйте города и регионы: инженерные статьи экстерриториальны.

**Критерий готовности:** LSI-термины присутствуют, каждый на своём месте, подмены сущностей нет.

## Шаг 11. Пройдите критерии «готово к SEO-ревью»

| Критерий | Проверка | Блок оценки |
|---|---|---|
| Answer First ≤ 40 слов | первый абзац | `intent` |
| H1 = интент | сравнить с брифом | `intent` |
| 4–6 H2 | структура | `intent` |
| Объём 5 500–7 000 | счётчик символов | `intent` |
| 3–4 блока расширения | наличие | `intent` |
| title ≤ 60 | подсчёт | `seo` |
| description ≤ 160 | подсчёт | `seo` |
| 4–6 FAQ | пары `q`/`a` | `seo` |
| schema и `additionalProperty` | паспорт заполнен | `seo` |
| LSI | 8–12 терминов | `seo` |

**Критерий готовности:** все пункты таблицы выполнены, статья уходит на ревью со статусом `review`.

## Плохо и хорошо

**1. Title и description для #47 «Набор инструментов для начинающего радиолюбителя».**
Плохо: title «Набор инструментов для начинающего радиолюбителя: полный список всего, что нужно купить, чтобы начать паять дома и не переплатить» — лимит 60 знаков превышен, интент размыт. Description «В этой статье мы поговорим о наборе инструментов» — анонс без ответа.
Хорошо: title «Набор инструментов начинающего радиолюбителя» — предмет и интент в лимите. Description даёт ответ: минимальный набор, что покупать первым, а что подождёт, и по какому критерию выбирать паяльник.

**2. Answer First для #26 «Холодная пайка: как распознать и переделать».**
Плохо: «Пайка — это процесс соединения металлических деталей припоем. В современном мире без пайки не обходится ни одно устройство». Определение из учебника и пустой зачин, ответа нет.
Хорошо: «Холодная пайка — шов, который застыл при подвижке детали: поверхность матовая и зернистая, контакт ненадёжный. Проверяется покачиванием вывода и прозвонкой, лечится перепайкой с фиксацией до полного застывания». Механизм, признак и действие в 40 словах.

**3. H2 для #16 «ПОС-61 и ПОС-40: в чём разница и что выбрать».**
Плохо: «Раздел 1. Общие сведения», «Раздел 2. Дополнительно» — заголовки ничего не обещают, читатель не понимает, где ответ.
Хорошо: «Чем ПОС-40 отличается от ПОС-61 по интервалу кристаллизации», «Какой припой брать для проводов, а какой для платы», «Где ошибка: паяют по уставке станции, а не по сплаву». Каждый H2 — обещание конкретного ответа.

## Чек-лист

- [ ] H1 называет интент брифа, без кликбейта.
- [ ] Под H1 ровно 4–6 H2, порядок соответствует типу статьи.
- [ ] Answer First укладывается в 40 слов, зачина-определения нет.
- [ ] `<title>` ≤ 60 знаков, содержит предмет и интент.
- [ ] `description` ≤ 160 знаков, даёт ответ, а не анонс.
- [ ] Slug совпадает с мастером, не изменён.
- [ ] Объём 5 500–7 000 знаков.
- [ ] Присутствуют 3–4 блока расширения, повторов нет.
- [ ] Warning стоит только там, где есть реальный риск.
- [ ] FAQ 4–6 пар, ответы 1–3 предложения, двойного вывода нет.
- [ ] Обязательные поля паспорта заполнены, «не применимо» осознанно.
- [ ] Температуры подтверждены паспортом факта, не подставлены.
- [ ] JSON-LD собирается автоматически, ручных копий нет.
- [ ] LSI 8–12 терминов, сущности не подменены.
- [ ] Города и регионы в тексте отсутствуют.

## Команды и файлы

```bash
python seo/scripts/build_worklist.py
python seo/scripts/link_candidates.py --id 16
python seo/scripts/score_article.py --file "<путь к тексту>" --id 16
```

| Команда | Назначение | Что смотреть |
|---|---|---|
| `build_worklist.py` | очередь и сводка по мастеру | `../out/WORKLIST.md` |
| `link_candidates.py --id N` | кандидаты связей для статьи | `../out/links-<id>.md` |
| `score_article.py --file --id` | блоки `intent`, `seo`, `facts` в баллах | `../out/scores/<id>.json` и `.md` |

`score_article.py` — основной инструмент проверки этого модуля: он считает длину title и description, число FAQ, объём, наличие Answer First. Скрипты контура создаются параллельно; запуск из корня репозитория.
