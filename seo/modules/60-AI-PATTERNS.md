# 60. ИИ-паттерны, JSON-контракт и порядок проверок

> Модуль отвечает на два вопроса: что в статье заполняется по готовым паттернам и кто проверяет результат. Голос и интонацию определяет [50-VOICE.md](50-VOICE.md), баллы — [40-SCORING.md](40-SCORING.md), формат публикации — [GUIDE.md](../../docs/03-editorial-publishing/GUIDE.md).

## Когда читать

- собираете статью из блоков по паттернам: TL;DR, Warning, Steps, диагностика, сравнение, FAQ;
- формируете JSON-контракт v1.1 для автоматической доставки;
- проверяете чужой черновик и не понимаете, почему он «звучит как ИИ»;
- готовите статью к блоку `ai` (10 баллов) и к гейтам до публикации;
- разбираетесь, кто и в каком порядке проверяет текст.

## Вход и выход

| | Что | Где лежит |
|---|---|---|
| Вход | статья в голосе Practico | файл или `topics.content_markdown` в `seo/data/seo.db` |
| Вход | паспорт факта: сплав, температуры, стандарт | бриф в таблице `briefs`, [реестр сплавов](../../theme4/data/materials-registry.php) |
| Вход | схема контракта | [article-contract-v1.1.schema.json](../../schemas/article-contract-v1.1.schema.json) |
| Выход | `package.json` для доставки | рабочий каталог `seo/out/` |
| Выход | отчёт оценки 0–100 | `seo/out/scores/<id>.json` и `.md` |
| Выход | черновик в WordPress | статус `draft` или `pending`, журнал `delivery-journal.json` |

## Что ИИ заполняет по паттернам

Паттерн — это готовая форма блока, которую генератор заполняет содержанием. Выбирайте только те блоки, которые объясняют тему: набор «все паттерны в каждой статье» даёт ровно тот эффект, от которого модуль защищает.

| Паттерн | Где в статье | Что заполняет ИИ | Что проверяет человек |
|---|---|---|---|
| TL;DR | первый абзац | прямой ответ в 1–2 предложениях | ответ совпадает с интентом, ≤ 40 слов |
| Warning | до опасного шага | предупреждение с граничным условием | риск назван, мера защиты конкретна, нет юмора |
| Steps | технологический раздел | последовательность действий | шаги выполнимы, нет пропущенного контроля |
| Symptom → Cause → Action | диагностика дефекта | симптом, причина, действие | причина физическая, а не «мастер ошибся» |
| Comparison | выбор сплава или инструмента | таблица по одинаковым параметрам | параметры сравнимы, цифры из реестра |
| FAQ | конец статьи | 4–6 пар `q`/`a` | ответы дополняют текст, не дублируют его |
| Sources | паспорт статьи | 2–4 источника `{title, standard, url}` | источники реальны, без `[web:*]` |
| Mistake | раздел «где ошибаются» | типичная ошибка и её цена | ошибка воспроизводима, цена правдива |

### Правила заполнения

- **TL;DR.** Пишите ответ, а не анонс: что выбрать, что сделать, при каких условиях. Запрещены «В этой статье…», «В современном мире…», «Давайте разберёмся».
- **Warning.** Формулируйте граничное условие: режим, материал, источник. «Будьте осторожны» — не предупреждение.
- **Steps.** Один шаг — одно действие. После шага, где возможна ошибка, добавляйте проверку: что должно быть видно, слышно или измеримо.
- **Symptom → Cause → Action.** Причина — физика: недогрев, перегрев, оксид, подвижка при остывании. Не «неопытность мастера».
- **Comparison.** Все варианты сравниваются по одним параметрам: солидус, ликвидус, рабочая уставка, прочность, отмывка. Цифры — только из реестра.
- **FAQ.** Вопросы берутся из брифа и реальных обращений. Ответ добавляет практическую грань, а не пересказывает абзац.
- **Sources.** ГОСТ, IPC, JEDEC, TDS производителя. URL ведёт на страницу документа или производителя, а не на поисковую выдачу.
- **Mistake.** После ошибки — безопасный откат: что делать, если перегрели, слиплись выводы, припой не лёг.

## Жёсткий JSON-контракт v1.1

Контракт — формат обмена между генератором и доставкой, а не обязательный интерфейс живого автора. Обязательные поля и ограничения задаёт схема; лишние ключи запрещены (`additionalProperties: false`).

| Поле | Тип | Ограничение и смысл |
|---|---|---|
| `content_id` | string | шаблон `^tchp-[a-z0-9-]+$` |
| `schema_version` | string | строго `1.1` |
| `title` | string | 10–200 символов, точный технический заголовок |
| `slug` | string | `^[a-z0-9-]+$` |
| `excerpt` | string | 20–300 символов, прямой ответ без кликбейта |
| `category_slug` | enum | `materialy`, `praktika`, `oshibki`, `start-i-baza`, `baza-znanij`, `oborudovanie` |
| `tags` | array | минимум 1 тег |
| `reading_time` | integer | 1–60 минут |
| `difficulty` | enum | `Новичок`, `Любитель`, `Практик`, `Инженер`, `Эксперт` |
| `solder_alloy` | enum | ключ сплава из реестра или `universal` |
| `temp_data` | object | `kind`, `range`; `peak` по необходимости |
| `content_html` | string | полный HTML статьи, не резюме |
| `faq` | array | 4–6 объектов строго `{q, a}` |
| `sources` | array | 2–4 объекта `{title, standard, url}` |
| `tools` | array | `{name, model, purpose}`, только реальное оборудование |

Канонический `solder_alloy`: `pos61`, `sn63pb37`, `pos40`, `sac305`, `sac405`, `sn42bi58`, `snbiago`, `roze`, `vuda`, `universal`. Другие значения схема не примет; сплав и температуры — только из [реестра](../../theme4/data/materials-registry.php).

`temp_data.kind`: `station_setpoint` — уставка станции, `joint_temperature` — температура соединения, `reflow_profile` — термопрофиль. `range` — рабочий диапазон, например для SAC305 это 217–220 °C по паспорту сплава; конкретные уставки под задачу берутся из брифа.

Минимальный каркас пакета:

```json
{
  "content_id": "tchp-pos61-pos40-20261028-01",
  "schema_version": "1.1",
  "title": "ПОС-61 и ПОС-40: в чём разница и что выбрать",
  "slug": "pos-61-i-pos-40-raznica",
  "excerpt": "Для плат и SMD берите ПОС-61, для проводов и клемм — ПОС-40.",
  "category_slug": "materialy",
  "tags": ["ПОС-61", "ПОС-40"],
  "reading_time": 6,
  "difficulty": "Новичок",
  "solder_alloy": "pos61",
  "temp_data": {"kind": "station_setpoint", "range": "260 – 295 °C"},
  "tools": [{"name": "Паяльная станция", "model": "—", "purpose": "Монтаж THT"}],
  "content_html": "<p>…</p>",
  "faq": [{"q": "…", "a": "…"}],
  "sources": [{"title": "ГОСТ 21930-76", "standard": "ГОСТ 21930-76", "url": "…"}]
}
```

Точные значения примера условны: перед доставкой они заменяются проверенными данными. Для тем без температурного режима (инструмент, химия, организация места) применяется ручная ветка публикации: `solder_alloy` = «— не применимо —», чекбокс температур снят.

## Что категорически нельзя

| Запрет | Почему | Как правильно |
|---|---|---|
| Ручной FAQ в `content_html` | шаблон темы выводит FAQ из метаполя; блок задвоится | только `faq` в контракте или метаполе |
| Выдуманные температуры и уставки | опасный совет, блокер независимо от суммы баллов | паспорт факта и реестр |
| Выдуманные источники и `[web:*]` | ломает доказательную базу и E-E-A-T | реальный ГОСТ, IPC или TDS с URL |
| Ключи `question`/`answer` | сервер вернёт `400 Bad Request` | строго `q` и `a` |
| Статус `publish` из скрипта | публикует человек после ОТК | только `draft` или `pending` |
| Поддельный `is_verified` | ломает знак качества и хеш | подтверждение делает человек в админке |
| «Не применимо» ради валидации | скрывает отсутствие данных | ручная ветка публикации или расширение схемы |

## Порядок проверок: шесть гейтов

Порядок фиксирован. Гейт нельзя пропустить или поменять местами: каждый следующий проверяет то, что уже прошло предыдущий.

| № | Гейт | Роль и модель | Вход → выход | Стоп-условие |
|---|---|---|---|---|
| 1 | Подготовка и LSI | **Бесплатный ИИ** (`dsh-freetap` / OpenCode Zen / DeepSeek Flash - 0 ₽) | бриф темы → сбор LSI, черновик H2/H3, драфты FAQ | нет первоисточников в брифе |
| 2 | Написание текста | **Автор** (`Claude Sonnet` / `Gemini 3.8 Pro` через Antigravity) | бриф + структура → полный текст статьи голосом Practico | выдуманный опыт мастера, нет температур |
| 3 | ИИ-паттерны | `slopmonster`, `deslop.py` + скрипт проверки | текст → отчёт по штампам и псевдовыводам | шаблонные зачины/финалы не вычищены |
| 4 | Рецензирование | **Рецензент** (`solder-reviewer`, второе мнение Gemini/Claude) | текст → независимый протокол замечаний | блокер по безопасности или температурам |
| 5 | Оценка 0–100 | Скрипт `seo/scripts/score_article.py` | файл статьи → расчёт 6 категорий и `score.json` | балл < 60 или критический блокер |
| 6 | Доставка | `tools/delivery_cli.py` | валидация контракта v1.1 → черновик (`draft`) в WordPress | ошибка схемы или конфликт 409 |
| 7 | **Приёмка и ОТК** | **Шеф-редактор (ВЫ)** | проверка предпросмотра theme4 → вердикт «Утверждено» → кнопка «🛡️ Подтвердить проверку (ОТК)» в админке | не подтверждено человеком |

Пороги оценки: **< 60** — в доработку, **60–79** — черновик, **≥ 80** — готово к передаче Вам на утверждение. Блокер останавливает статью при любой сумме.

### Разделение задач между бесплатными и сильными моделями:
1. **Бесплатные модели (OpenCode Zen / freetap / DeepSeek Flash - 0 ₽):**
   - Выполняют всю черновую работу: парсинг конкурентов, подбор ключевых слов, извлечение терминов, драфты вопросов FAQ, авто-проверку длины предложений и HTML-тегов.
2. **Премиум-модели (Claude Sonnet / Google Gemini 3.8 Pro):**
   - Пишут основной текст статьи в строгом соответствии с профилем голоса Practico ([50-VOICE.md](50-VOICE.md)).
   - Проводят глубокое инженерное рецензирование и фактчекинг физико-химических процессов пайки.
3. **Шеф-редактор (Вы):**
   - Принимаете окончательное решение: статья либо утверждается к публикации, либо возвращается на доработку по списку замечаний из отчёта скоринга.

### Соответствие стандартам темы theme4:
- **Паттерны Gutenberg:** использовать только зарегистрированные паттерны (`tochka-plavleniya/tldr-center`, `tochka-plavleniya/safety-warning`, `tochka-plavleniya/tools-needed`, `tochka-plavleniya/section-diagnostics`).
- **Защита от дублей FAQ:** блок FAQ **категорически запрещено** вставлять вручную в тело статьи (`content_html`). Он заполняется строго в массиве метаполя `tchp_faq_items` (4–6 пар `q`/`a`) и рендерится шаблоном темы `theme4/single.php` автоматически.
- **Иконки:** запрещено использовать эмодзи в качестве иконок в интерфейсе. Тема использует только векторный монохромный SVG.
- **DOM-якоря:** все заголовки H2 и H3 автоматически дедуплицируются функцией `tchp_process_article_anchors()` темы `theme4`.

- `solder-writer` не публикует и не присваивает `verified`. Он отдаёт текст и служебную записку.
- `slopmonster` ищет шаблонные формы, но не проверяет факты. Его результат — повод перечитать, а не приговор.
- `solder-reviewer` выносит вердикт «Принято к упаковке» или возвращает протокол. Вердикт редактора не равен WordPress `verified`.
- `score_article.py` считает баллы; блок `ai` весит 10, блок `facts` содержит блокеры.
- `delivery_cli.py` валидирует контракт и создаёт только черновик. После отправки он перечитывает запись и сверяет поля; расхождение — код `4`.
- Человек подтверждает редакцию кнопкой ОТК и публикует. Любая правка после подтверждения сбрасывает статус.

## Правила AI-детекторов

- **`deslop.py` — англоязычные правила.** Проверяются пять категорий: лексика, конструкции, пунктуация, тройные перечисления, возможные недоказанные числа. 5/5 означает «ни один шаблон не совпал», а не «текст хороший». Ниже 5/5 — код выхода 1.
- **Русский язык детектор не распознаёт.** Правила написаны для английского и не определяют язык входа. Для русских статей используйте отчёт как каталог признаков, а решение принимайте после чтения.
- **Ложные срабатывания нормальны.** Термин «надёжный», длинное техническое условие, необходимое перечисление могут совпасть с правилом. Сначала прочитайте совпадение, потом правьте.
- **Не оптимизируйте текст под детектор.** Запрещено прятать прозу в блоки кода, дробить фразы ради счёта и добавлять «личность» искусственно.
- **Второй проход — другой моделью.** `slopmonster` требует редактуру моделью другого семейства; её предложения проверяются, а не принимаются вслепую. Если второй проход не выполнен, это фиксируется.
- **Оценка `ai` в `score_article.py`.** Блок весит 10 баллов: учитываются шаблонные зачины и финалы, паттерны и уникальность ≥ 85%. Конкретный порог паттернов задаётся в реализации — [уточнить у владельца].
- **Детектор не доказывает авторство.** Ни один отчёт не подтверждает, что текст написал человек. Итоговое решение — за редактором.

## Шаги: прогнать статью по конвейеру

1. Проверьте, что статья написана голосом Practico и содержит паспорт факта.
2. Соберите паттерны: TL;DR, шаги, предупреждения, диагностику, FAQ, источники.
3. Прогоните `deslop.py` и разберите каждое совпадение в контексте.
4. Отдайте текст `solder-reviewer` и закройте протокол замечаний.
5. Соберите `package.json` строго по схеме v1.1, без ручного FAQ в теле.
6. Запустите оценку; при результате < 80 вернитесь к правке, а не к публикации.
7. Отправьте черновик через `delivery_cli.py` и передайте человеку на ОТК.

## Плохо и хорошо

| Плохо | Хорошо |
|---|---|
| «В современном мире пайка окружает нас повсюду, и умение паять — важный навык». | «Для плат и SMD берите ПОС-61: он застывает почти сразу». |
| «Будьте осторожны при пайке!» | «Дым флюса раздражает слизистые: работайте с вытяжкой или дымоуловителем». |
| «ПОС-61 лучше ПОС-40». | Таблица: солидус 183 °C у обоих, ликвидус 190 °C против 238 °C, интервал 7 °C против 55 °C. |
| FAQ дословно повторяет абзац статьи. | FAQ отвечает на смежный вопрос: «Можно ли смешивать ПОС-61 и ПОС-40?» |
| «Результат? Идеальный шов». | «Шов блестящий и гладкий, припой растёкся по площадке». |
| Источник: `[web:64]`. | Источник: ГОСТ 21930-76, раздел о химическом составе. |

## Чек-лист «не звучит как ИИ»

- [ ] Нет зачина «В современном мире», «В этой статье», «Давайте разберёмся».
- [ ] Нет финала «Подведём итоги», «В заключение», «Таким образом».
- [ ] Нет конструкции «не просто X, а Y» и «это больше, чем…».
- [ ] Нет дежурных «важно отметить», «стоит подчеркнуть», «именно поэтому».
- [ ] Нет самовопросов и самоответов: «Результат? Отличный».
- [ ] Нет троек прилагательных «быстро, надёжно, качественно».
- [ ] Нет цепочек тире на полстроки и перегруженных составных прилагательных.
- [ ] Каждый абзац добавляет новый факт, а не пересказывает предыдущий.
- [ ] Нет пустых контрастов и повторяющихся метафор.
- [ ] Нет выдуманных чисел, клиентов, отзывов и результатов.
- [ ] FAQ не дублирует тело статьи и не выводится дважды.
- [ ] Источники реальны, без `[web:*]` и плейсхолдеров.
- [ ] Уникальность текста ≥ 85% по оценке.
- [ ] Отчёт детектора разобран вручную, спорные совпадения объяснены.

## Команды и файлы

```bash
# 1. ИИ-паттерны: пять категорий, 5/5 — совпадений нет
python .agents/skills/slopmonster/tools/deslop.py "сами статьи/17-bessvincovyj-pripoj.md"

# 2. Оценка 0–100 с отчётом в seo/out/scores/
python seo/scripts/score_article.py --file "сами статьи/17-bessvincovyj-pripoj.md" --id 17

# 3. Доставка черновика (после валидации контракта скриптом)
python tools/delivery_cli.py send-draft --file seo/out/package.json \
  --wp-url "https://tochka-plavleniya.ru" --wp-user "automation_bot" --wp-pass "xxxx xxxx xxxx xxxx"

# 4. Внести принятый текст в БД (с резервной копией)
python seo/scripts/sync_all_texts_to_db.py
```
