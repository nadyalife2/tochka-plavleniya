# Субагент: 00-research (Разведчик конкурентов и приоритетов)

> **Исполнитель:** `research_competitors.py` + `priority_matrix.py` — локальные Python-скрипты  
> **Стоимость:** **0 ₽, 0 токенов**  
> **Задача:** Собрать статьи конкурентов, разложить их по кластерам, найти пробелы и посчитать приоритет каждой темы плана.

Это первый шаг конвейера. Он отвечает на вопрос, который в Excel раньше решался вручную:
**«Что писать первым и почему именно это»**.

---

## 1. Входные данные

Единственный мастер — SQLite `seo/data/seo.db`. Excel-архив `semantic_core_FULL_v11.xlsx`
для работы не читается.

| Что | Где лежит |
|---|---|
| Список конкурентов | таблица `competitors` (+ `competitors_proposed`) в `seo/data/seo.db` |
| Кластеры, пробелы, приоритеты | таблица `clusters` |
| План тем | таблица `topics` |
| Карта перелинковки | таблица `links` |

## 2. Что делает агент

### Шаг 1. Скан конкурентов

```bash
python seo/scripts/research_competitors.py --limit 60
```

Обходит для каждого домена из `competitors`:

1. `sitemap.xml`, `sitemap_index.xml`, `wp-sitemap.xml`, `sitemap-1.xml`, `blog/sitemap.xml` —
   с разворотом вложенных sitemap-индексов.
2. RSS/Atom: `/rss`, `/rss.xml`, `/feed`, `/feed.xml`, `/atom.xml`, `/blog/rss.xml`, `/ru/rss/`,
   плюс автопоиск `<link rel="alternate" type="application/rss+xml">` в `<head>` главной.
3. HTML-архив блога: ссылки, похожие на статьи (`/blog/`, `/article/`, `/2026/`, `/publication/`).
4. Для URL без заголовка — догружает страницу и берёт `<h1>`, иначе `<title>`.

Мусорные URL отсекаются регуляркой `JUNK`: рубрики, теги, авторы, пагинация, корзина,
политики, `wp-json`, `wp-admin`, комментарии.

Каждая найденная статья классифицируется двумя эвристиками:

- **тип:** `buyer's guide`, `сравнение`, `инструкция`, `топ ошибок / проблема-решение`,
  `рейтинг / обзор бренда`, `обучающий / что такое`, `статья / гайд`;
- **кластер:** `Материалы / Припои`, `Материалы / Флюсы`, `Ошибки / Проблемы новичка`,
  `Инструменты / Выбор паяльника`, `Инструменты / Рейтинг паяльников`,
  `Ремонт электроники`, `Основы пайки / Как паять`, `Типы компонентов / SMD`, `Прочее`.

Результат пишется в таблицу `raw_articles` (ключ — `url`, дубли пропускаются), счётчик
`articles_count` в таблице `competitors` инкрементируется по каждому домену.
Перед записью автоматически создаётся бэкап базы в `seo/data/_backup/`.

### Шаг 2. Матрица приоритетности

```bash
python seo/scripts/priority_matrix.py --top 20
```

Считает для каждой темы интегральный балл 0–100 по шести факторам с весами:

| Фактор | Вес | Как считается |
|---|---:|---|
| `cluster_score` | 0.25 | приоритет кластера: 🔴 высокий = 100, 🟡 средний = 65, 🟢 низкий = 35 |
| `gap_score` | 0.20 | текст колонки «пробел»: «нет сильного контента» = 95, «частично» = 70, пусто = 55 |
| `coverage_score` | 0.15 | сколько статей конкурентов попало в этот кластер по `raw_data`: 0 → 100, >20 → 15 |
| `links_score` | 0.15 | хабность: `2 × входящие + исходящие`; ≥14 → 100 |
| `keywords_score` | 0.10 | число ключевых сущностей кластера; ≥6 → 100 |
| `readiness_score` | 0.15 | есть бриф → 100, с нуля → 70, текст уже есть → 40 |

Пишется в таблицу `topics`: `priority_score`, а детализация факторов — в `seo_priority_json`; итоговый балл 0–100 дублируется в `seo_priority`.

Пороговые корзины:

- **90–100** — брать сейчас;
- **75–89** — следующая волна;
- **60–74** — позже;
- **0–59** — в конец очереди.

### Шаг 3. Обновление очереди

```bash
python seo/scripts/build_worklist.py
python seo/scripts/build_dashboard_ui.py
```

`WORKLIST.md` пересобирается с учётом приоритетов, дашборд показывает новую колонку «Разведка».

## 3. Ограничения и что делать, когда скрипт не справляется

| Ситуация | Признак | Решение |
|---|---|---|
| Сайт рендерит контент через JS | В ответе пустой каркас, ссылок нет | Playwright MCP или `transport: streamable-http` |
| Антибот (Cloudflare, Qrator) | `HTTP 403` на любой запрос | Firecrawl MCP с его прокси-пулом |
| Нужна очистка страницы в Markdown | Скрипт берёт только заголовки | Firecrawl `/scrape` |
| Нужны позиции в поиске | Скрипт не ходит в поисковики | SerpAPI, Tavily, Brave Search |

Подробности подключения — [MCP-SETUP.md](MCP-SETUP.md). **Правило проекта: не подключать
MCP раньше, чем исчерпан бесплатный скрипт.**

---

## 4. Известное ограничение песочницы

В режиме `workspace-write` дочерние процессы не могут открывать именованные каналы:
`stdio`-MCP серверы (Playwright, `firecrawl-mcp`) падают с `WinError 5` / `EPERM`.
Проверено на практике: Playwright Python упал именно так. Рабочие варианты —
`streamable-http`, осознанный `danger-full-access` для одного запуска, либо отказ от MCP
в пользу HTTP из Python-скрипта.
