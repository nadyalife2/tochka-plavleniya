## Структура: 5 Gems + что в них прописывать

Каждый Gem — это одна роль в конвейере. Меняется только тематика (в моих примерах — пайка), сама логика универсальна для любого нишевого сайта.


| Gem | Роль | Что обязательно прописать в System Instructions |
| :-- | :-- | :-- |
| 1. Researcher | Собирает факты и структуру темы | Аудитория, цель сайта, запрет на выдумывание фактов, формат ответа (5 пунктов), связь с таблицей semantic_core |
| 2. Writer | Пишет текст статьи | Шаблон статьи (H2-блоки), список запрещённых фраз, стиль (спокойный/экспертный), формат Markdown с front matter |
| 3. Reviewer | Проверяет качество и безопасность | Критерии оценки 0-100 по 5-6 параметрам, вердикт (готово/доработать/не публиковать), словарь терминов для проверки |
| 4. SEO-Planner | Планирует title/H2/meta | Правила SEO без спама, привязка к семантическому ядру (clusters, competitors) |
| 5. WordPress-Publisher | Готовит к публикации | Чек-лист перед публикацией, формат slug/excerpt/тегов |

Для каждого Gem нужен один общий набор "файлов знаний" (Knowledge) плюс один уникальный файл-инструкция роли.

## Какие файлы нужны (универсальный набор)

Загружай как Knowledge файлы в КАЖДЫЙ из 5 Gems — они формируют общий контекст, одинаковый для всех ролей:

- **01_project_goal.md** — аудитория, тематики сайта, принципы (полезно/понятно/безопасно)
- **02_style_guide.md** — правила стиля текста
- **03_safety_rules.md** — правила безопасности (если тема связана с рисками — техника, здоровье, деньги)
- **04_forbidden_phrases.txt** — стоп-лист рекламных клише
- **05_terminology.md** — словарь терминов ниши
- **06_article_template.md** — структура статьи (H2-блоки)
- **07_seo_rules.md** — правила SEO без спама
- **08_wordpress_prep.md** — чек-лист публикации
- **09_habr_like_style.md** (опционально) — если нужен экспертный, не рекламный тон
- **Instrukciya-dlia-[Role].md** — уникальный промпт именно этой роли

Для нового сайта просто копируешь всю папку файлов, меняешь content внутри (тематику, термины, риски), названия файлов оставляешь те же — так проще масштабировать шаблон на любую нишу.

## Какие поля нужны в таблице semantic_core

Таблица — общий источник данных для всех Gems, универсальная структура на 4 листа:

- **content_plan**: рабочий заголовок, slug, тип статьи, приоритет, статус
- **clusters**: название кластера, ключевые темы (H2), пробел у конкурентов, приоритет
- **raw_data**: url, title, source, дата, cluster — сырые источники и конкурентские материалы
- **competitors**: домен, заметки о структуре конкурента, ссылка на материал, вес/авторитетность


## Как использовать Firecrawl

Firecrawl — это API, который превращает любую веб-страницу в чистый Markdown или структурированные JSON-данные, что идеально для сборки raw_data и competitors без ручного копирования. Практическая схема для Gem-конвейера:[^1]

- **Заполнение raw_data**: используй Firecrawl Search (2 кредита за 10 результатов) или Crawl (1 кредит/страница), чтобы найти статьи конкурентов по ключу и получить их в Markdown[^1]
- **Анализ competitors**: команда Scrape с опцией "main content only" убирает навигацию и футер, оставляя только текст статьи — удобно для сравнения структуры H2[^2]
- **Batch-режим**: если у тебя список из 20-50 URL конкурентов, используй Batch Scraping — один вызов вместо 20 отдельных запросов, дешевле по кредитам[^2]
- **Бюджет**: бесплатный тариф даёт 1000 страниц/мес, чего обычно хватает для сбора конкурентного контента под 1 нишевый сайт; при масштабировании на несколько сайтов переходи на Hobby за \$16/мес (5000 страниц)[^1]

Порядок действий: сначала Firecrawl собирает сырые данные (raw_data + competitors) → эти данные вручную вставляешь в таблицу semantic_core → потом Gem 1 (Researcher) работает уже с готовой таблицей, а не с сырым HTML.

## Какие расширения (форматы) выходных файлов нужны

- **Markdown (.md)** — все инструкции для Gems и готовые статьи (легко читается любой моделью, не требует парсинга)
- **.txt** — только для простых списков без структуры (forbidden_phrases)
- **.xlsx / Google Sheets** — таблица semantic_core (нужна фильтрация, сортировка, статусы)
- **.json** — только если позже подключаешь автоматизацию (n8n, API) — тогда verdict/score от Reviewer'а удобно получать в JSON


## Пошаговый алгоритм запуска нового сайта

1. Определи тематику и аудиторию — заполни project_goal.md
2. Собери конкурентов и сырые данные через Firecrawl → сложи в raw_data и competitors
3. Составь content_plan (30-50 рабочих заголовков) и clusters (сгруппируй по темам)
4. Создай 5 Gems, в каждый загрузи общий набор файлов + уникальную инструкцию роли
5. Прогони темы через Researcher (пакетно) → Writer → Reviewer → SEO-Planner → WordPress-Publisher
6. Публикуй вручную или подключай n8n, если объём вырастет и ручной режим станет неэффективным

Такой шаблон переносится на любую нишу за 1-2 часа — меняются только сами тексты внутри файлов знаний, структура и логика остаются одинаковыми.
